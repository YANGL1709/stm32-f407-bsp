# CAN：从位定时到 Bus-Off，一条链上踩了十一个坑

- 日期：2026.11.19 – 11.28
- 实际投入：约 30 小时（估）

## 要解决什么问题

不查库函数，用寄存器把 CAN1 跑通：

1. 算位定时（500 kbps，采样点落在 75–87.5%）
2. 标准帧 + 扩展帧收发
3. 过滤器掩码 / 列表
4. 中断接收 + 软件队列
5. 错误处理：TEC/REC/LEC 全解码，Bus-Off 产生与恢复

顺序：先 Loopback 自测（隔离"内核"和"外部电路"），再上真实双绞线双板对发，最后做故障注入。

## 试过哪些方案（含失败的）

| 方案 | 结果 | 结论 |
|---|---|---|
| 单节点发帧，等对端 ACK | TEC 冲到 **128 就停**，无限重传 | ❌ **永远到不了 Bus-Off**，见 §踩的坑 7 |
| `CAN_H` 短接到地 | LEC 3→5，TEC 128→248 → **BOFF** | ✅ 唯一能单板复现 Bus-Off 的办法 |
| 拔掉总线 / 总线断开 | TEC 卡 128 | ❌ 同上，只有 ACK 错误 |
| Loopback 自测 | 收发全通 | ✅ 排障时用来隔离内核与外部电路 |
| PCAN-View Listen-Only 做"无 ACK"环境 | 还能收到帧 | ⚠️ 数据在 ACK 槽之前就发完了，**收到 ≠ 确认** |
| 1 秒打印一次看 TEC 爬升 | 只看到终值 | ❌ 128→248 全程几毫秒，采样必须 ≤10ms |

## 最终方案 & 为什么是它

**时钟与引脚**：PB8 = CAN1_RX、PB9 = CAN1_TX，AF9；CAN 时钟 = PCLK1 = **42 MHz（不翻倍，只有 TIMx 翻倍）**。

**初始化顺序（不能乱）**

1. 清 `MCR.SLEEP` → 等 `MSR.SLAK` 清零
2. 置 `MCR.INRQ` → 等 `MSR.INAK` 置位
3. 写 `BTR`（位定时只能在这个窗口写）
4. 清 `MCR.INRQ` → 等 `MSR.INAK` 清零

**位定时**：`BTR = 0x001A0005`（SJW=0、TS2=1、TS1=10、BRP=5）
→ 42MHz ÷ 6 = 7MHz，14 tq/bit，**500 kbps**，采样点 **85.7%**

**过滤器**：32 位尺度 + 掩码模式，见 §怎么验证的

**接收**：中断（`FMPIE0`）+ 16/32 深软件队列，主循环 `CAN_PopRx` 消费

**为什么是这套**：零 HAL、每一层都能用示波器/寄存器立刻验证；失败时能按"波形 → 电阻 → 波特率 → 过滤器 → 代码"逐层排除。

## 踩的坑

### 坑 1：位定时按 84 MHz 算，怎么都对不上
- 现象：算出来 1 Mbps，示波器量出来不是
- 根因：**CAN 挂 APB1 = 42 MHz，不翻倍**；只有 TIMx 在 APB1 分频≠1 时才 ×2
- 教训：TIM 84 / CAN 42 / UART·SPI 84（挂 APB2 的才是 84）

### 坑 2：`FS1R &= ~FSC0` 以为是 32 位
- 现象：**没有现象**，一切正常
- 根因：`FSC0=0` 是 16 位，`=1` 才是 32 位；注释写"32 位"，代码是 16 位
- 为什么没暴露：`FR1/FR2` 都写 0，掩码全 0 → 全放行，配错也看不出来
- 教训：**掩码全 0 会让"配错"看起来"能用"**，验证过滤器必须先配真掩码

### 坑 3：发送死等 `while (!(TSR & TME0))`
- 现象：总线异常时主循环永久卡死，串口不再打印、按键也死
- 根因：无超时
- 修复：`timeout = 200000U; while (...) --timeout; if (!timeout) return;`
- 教训：**所有等硬件的 while 都要带超时**

### 坑 4：`ESR` 里 TEC/REC 读反
- 现象：一直以为 TEC 是 0，怀疑"我怎么不报错"
- 根因：`TEC` 在 bit23:16、`REC` 在 bit31:24，凭记忆写成 `>>24` 是 TEC
- 教训：以 CMSIS 头文件的 `CAN_ESR_TEC_Pos` 为准，不要背

### 坑 5：DLC 没做上限，踩栈
- 现象：对端发 DLC>8 的帧时跑飞
- 根因：DLC 4 位合法值 0–15，9–15 按 8 字节处理，但循环按 `len` 走，越界写 `data[8]`
- 修复：`if (msg->len > 8U) msg->len = 8U;`

### 坑 6：PB8 没上拉
- 现象：不接收发器时偶发"总线一直在忙"
- 根因：RX 浮空被读成显性
- 教训：输入脚先给确定电平，别指望悬空

### 坑 7：单节点永远进不了 Bus-Off（核心认知）
- 现象：TEC 涨到 **128 就不再动**，无限重传，示波器上干干净净
- 根因：ISO 11898-1 规则 3 的**例外 1**——error-passive 节点检测到 **ACK 错误**时，TEC 不再累加
- 推论：**只产生 ACK 错误的场景（单节点 / 总线断开）永远到不了 Bus-Off**，会安静停在 error-passive
- 代价：一开始以为是自己代码没进 BOFF，查了一整晚

### 坑 8：被动错误帧在示波器上"看不见"
- 现象：复位后第一帧能看到 6 个显性位的错误标志，跑几毫秒后就再也看不到，但 TEC 一直是 128
- 根因：TEC > 127 后节点进入 error-passive，错误标志从 **6 个显性**变成 **6 个隐性**；而且这 6+8 个隐性位正好顶替了「ACK 分隔符 + EOF」的位置，电平上完全一致
- 验证：示波器单次触发 + 复位，抓第一帧能见 12 µs 显性块（2 µs/div 下 6 格）；4 ms 后再抓就没有
- 教训：**"看不见错误帧"不等于"没在发错误帧"**，要看节点是不是已经被动

### 坑 9：1 秒采样看不到 TEC 爬升
- 现象：`[21s] TEC=128` → `[22s] TEC=248 BOFF`，中间过程全丢
- 根因：128→248 只要 15 次错误、约 4 ms
- 修复：采样降到 10 ms，且"只在变化时打印"

### 坑 10：计数器声明在 `while(1)` 里 → 每轮清零
- 现象：`isr_rx` 在涨（2000/s），但 `rx_in` 恒为 0，很容易误判成"过滤器把该收的也挡了"
- 根因：

```c
while (1) {
    uint32_t rx_in = 0;        /* ← 每圈重置 */
    while (CAN_PopRx(&m)) { if (m.id == ...) rx_in++; }
    printf("rx_in=%u", rx_in); /* 永远是 0 */
}
```

- 修复：把累计量的声明挪到 `while(1)` 外面
- 教训：**凡是要跨循环累计的量，声明必须在循环外**

### 坑 11：`printf` 会吃掉接收带宽
- 现象：2000 fps 下 `drop` 以约 6 帧/秒增长
- 根因：每行 printf ≈ 5 ms 阻塞（115200），每秒两行 → 主循环停 10 ms → 2000 fps × 0.01 s = 20 帧，16 深队列扛不住
- 定量验证：队列 16 时**每次打印正好丢 7 帧** = (16+7) 帧 × 0.5 ms ≈ 11.5 ms 阻塞
- 修复：队列 16 → 32 → 稳态零丢帧
- 教训：日志必须**环形缓冲 + DMA**，或至少满足 `深度 > 到达率 × 最长阻塞时间`

### 附带发现：`FMR` 读出异常值

```
FMR = 0x2A1C0E00
```

按 RM0090 只有 `CAN2SB[13:8]` 和 `FINIT[0]` 有效，高 18 位是保留位（应为 0）。功能位正确（`CAN2SB=14`、`FINIT=0`），**疑似兼容片**（GD32 / APM32 / CKS32）。以后遇到"寄存器行为和手册不符"，先怀疑这个。

## 关键数字

| 项 | 值 |
|---|---|
| CAN 时钟 | PCLK1 = 168 MHz / 4 = **42 MHz** |
| 位定时 | BRP=5（÷6）→ 7 MHz；1+11+2 = **14 tq** |
| 波特率 / 采样点 | **500 kbps** / **85.7%** |
| `BTR` | **0x001A0005** |
| 1 bit / 8 字节扩展帧 | 2 µs / 128 bit = **256 µs** |
| 过滤器范围 | `0x17180000 ~ 0x1718FFFF`（`FR2=0x0xFFF80004`） |
| Bus-Off 恢复 | **2841 µs**（理论 2816 µs，误差 0.9%） |
| 队列容忍 | 32 深 ÷ 2000 fps = **16 ms** |

## 怎么验证的（给数据）

**① 位定时**：示波器看差分波形，显性 ≈2 V、隐性 ≈0 V，位宽 **2.0 µs**，与 BRP 计算吻合。

**② 收发**：扩展帧 `0x1718AAF1` + 8 字节 `81 82 83 84 85 86 87 88`，双板对发 + 逻辑分析仪解出 ID 与数据。

**③ 过滤器掩码**（11-28）

```c
CAN1->FMR  |=  CAN_FMR_FINIT;
CAN1->FM1R &= ~CAN_FM1R_FBM0;      /* 掩码模式 */
CAN1->FS1R |=  CAN_FS1R_FSC0;      /* 32 位尺度 */
CAN1->FFA1R &= ~CAN_FFA1R_FFA0;    /* → FIFO0 */
CAN1->sFilterRegister[0].FR1 = (0x1718AAF1U << 3) | 0x04;   /* 0xB8C5578C */
CAN1->sFilterRegister[0].FR2 =  0xFFF80000U      | 0x04;    /* 0xFFF80004 */
CAN1->FA1R |=  CAN_FA1R_FACT0;
CAN1->FMR  &= ~CAN_FMR_FINIT;
```

掩码只看 bit31:19 = `STID[10:0] + EXID[17:16]`，即要求 `ID[28:16] = 0x1718`，低 16 位任意。

| PCAN 发的 ID | 周期 | 段内？ | 实测 |
|---|---|---|---|
| `0x1718DAF1` | 1 ms | ✅ | **1000 /s** |
| `0x17184474` | 1 ms | ✅ | **1000 /s** |
| `0x17178544` | 2 ms | ❌ | **0（恒为零）** |

`isr_rx` 增速 2000/s = 两个段内 ID 之和；**9 万帧样本，段外 0 误收**。

**④ 错误状态**（单板，500 kbps，ABOM=0）

| 阶段 | 条件 | 结果 |
|---|---|---|
| ① | 无 ACK | `ESR=0x00800033`，**TEC=128**，LEC=3（ACK 错误），PASSIVE |
| ② | `CAN_H`→GND | `ESR=0x00F80057`，**TEC=248**，LEC=5（位显性错误），**BOFF** |
| ③ | 撤线 + `INRQ 1→0` | **2841 µs** 后 BOFF 清零，TEC 归零再爬回 128 |

**⑤ 吞吐**：2000 fps（51% 总线占用），稳态丢帧 **0**，`max_loop=13 ms`。

## 还没搞清的

1. **`FMR` 高 18 位为什么读出 `0x2A1C0000`** —— 兼容片？勘误？没定论
2. **启动瞬态那 72 帧丢在哪** —— 怀疑是 `CAN_Init()` 的两行寄存器打印 + 首次 `CAN_SendMsg` 等待叠加，但 `max_loop` 没抓到对应尖峰（因为发生在 while 循环之前）
3. **列表模式没实测** —— 只验证了 32 位掩码；16 位尺度和列表模式还是纸面知识
4. **CAN2 完全没用过** —— 双 CAN 网关要用，留到寒假
5. **采样点只算了没测** —— 85.7% 是 BTR 算出来的，没做过"扫解码窗口"的实测
